# Laravel Structure Beginner Guide for ELMS

This guide explains the Laravel folders, common Laravel terms, and how each part is used in this ELMS project.

ELMS means Employee Leave Management System. In this project, Laravel is used to handle login, role-based pages, leave filing, leave approval, employee records, leave balances, reports, calendars, notifications, and CSV exports.

## 1. Big Picture

Laravel is a PHP web framework. A framework gives the project a standard structure so developers know where to place routes, controllers, models, views, validation, database files, tests, and configuration.

The most important idea is MVC:

| MVC Part   | Meaning | ELMS Location | ELMS Example |
| ---------- | --- | --- | --- |
| Model      | Represents database data and business relationships | `app/Models` | `LeaveApplication`, `Employee`, `LeaveBalance` |
| View       | The HTML page shown to the user | `resources/views` | `employee/leaves/index.blade.php` |
| Controller | Receives the request, talks to models, then returns a view or redirect | `app/Http/Controllers` | `Employee/LeaveApplicationController.php` |

Simple ELMS request flow:

```text
Browser
  -> public/index.php
  -> bootstrap/app.php
  -> routes/web.php
  -> middleware checks
  -> controller method
  -> form request validation, if needed
  -> Eloquent models and database
  -> Blade view or redirect response
  -> Browser
```

Example: when an employee files a leave request:

```text
POST /employee/leaves
  -> routes/web.php
  -> auth, profile.complete, account.approved, role:employee middleware
  -> Employee\LeaveApplicationController@store
  -> StoreLeaveApplicationRequest validates the form
  -> EmployeePortalController@storeLeave creates a LeaveApplication
  -> LeaveBalance may be updated
  -> SystemNotification sends an in-app alert
  -> user is redirected back to the leave page
```

## 5. Middleware

Middleware are filters that run before or after a request reaches the controller. In ELMS, middleware protects pages from users who should not access them.

Middleware aliases are registered in `bootstrap/app.php`:

| Alias | Class | Purpose |
| --- | --- | --- |
| `role` | `RoleMiddleware.php` | Checks if the logged-in user has the required role |
| `account.approved` | `EnsureAccountApproved.php` | Blocks pending or inactive users from protected areas |
| `profile.complete` | `EnsureProfileComplete.php` | Ensures the user has completed required profile data |

Examples from `routes/web.php`:

```php
Route::middleware(['account.approved', 'role:manager'])
    ->prefix('manager')
    ->name('manager.')
    ->group(function () {
        Route::get('/dashboard', [ManagerDashboardController::class, 'index'])->name('dashboard');
    });
```

This means only approved manager accounts can access `/manager/dashboard`.

## 7. Models and Eloquent ORM

Eloquent is Laravel's ORM. ORM means Object-Relational Mapper.

In simple words, Eloquent lets the project work with database tables using PHP classes instead of writing raw SQL for every query.

Example:

```php
$employee = Employee::with('leaveBalances')->find($id);
```

This means "get an employee record and also load that employee's leave balances."

Current ELMS models:

| Model | Database Meaning | Important Relationships and Functions |
| --- | --- | --- |
| `User` | Login account | Has one `employee`, belongs to `department` and `position`, has many `notifications`; includes `derivedRole`, `isHR`, `isManager`, `isEmployee`, `hasAccessRole`, and `getAccessLevel` |
| `Employee` | HR employee profile | Belongs to `user`, `departmentRecord`, `positionRecord`, and `manager`; has many `leaveApplications` and `leaveBalances`; includes `full_name` accessor, employee ID generation, department/position helpers, and role derivation |
| `Department` | Company department | Has manager user, employees, positions, and users |
| `Position` | Job position under a department | Belongs to department; has many users and employees |
| `LeaveType` | Type of leave | Has many applications and balances; includes `isVisibleForGender` for maternity/paternity and gender-specific leave rules |
| `LeaveApplication` | A filed leave request | Belongs to employee, leave type, and reviewer |
| `LeaveBalance` | Leave credits per employee, type, and year | Belongs to employee and leave type; includes `remaining_days` accessor |
| `SystemNotification` | In-app notification | Belongs to user; includes notification sending, actionable notification filtering, unread count logic, and leave-request settlement |

Important Eloquent terms in this project:

| Term | Meaning | ELMS Example |
| --- | --- | --- |
| Model | PHP class representing a database table | `Employee` represents `employees` |
| Table | Database storage for records | `leave_applications` stores leave requests |
| Record | One row in a table | One submitted sick leave request |
| Primary key | Unique ID of a record | `id` column |
| Foreign key | Column that links one table to another | `leave_applications.employee_id` links to `employees.id` |
| Relationship | Function that describes how models connect | `Employee::leaveApplications()` |
| `belongsTo` | This model points to one parent model | A leave application belongs to one employee |
| `hasMany` | This model owns many related records | An employee has many leave applications |
| `hasOne` | This model owns one related record | A user has one employee profile |
| `$fillable` | Fields that can be mass assigned | `LeaveApplication` allows `employee_id`, `leave_type_id`, dates, status, and remarks |
| `$casts` | Converts database values to useful PHP types | `start_date` becomes a date object; booleans become true/false |
| Accessor | Method that creates a computed attribute | `getFullNameAttribute` creates `$employee->full_name` |
| Query scope | Reusable query condition | `scopeUnreadActionable` filters unread useful notifications |
| Route model binding | Laravel automatically finds a model from a route parameter | `/employee/leaves/{leaveApplication}` gives the controller a `LeaveApplication` object |

## 20. Defense-Friendly Explanation

You can explain the project like this:

> Our ELMS follows Laravel MVC. The routes in `routes/web.php` receive browser requests and group them by role: HR/Admin, Manager, and Employee. Middleware checks authentication, approval status, profile completion, and role access. Controllers in `app/Http/Controllers` handle each module. Models in `app/Models` use Eloquent ORM to connect to database tables such as users, employees, leave applications, leave balances, and notifications. Blade files in `resources/views` display the pages. Migrations and seeders in `database` define and populate the database. Fortify handles authentication, while our custom middleware and model methods enforce role-based access for the ELMS workflow.

Short example:

> For leave filing, the employee route calls `LeaveApplicationController`. The form is validated by `StoreLeaveApplicationRequest`. The system saves the leave using the `LeaveApplication` Eloquent model, checks balances through `LeaveBalance`, and alerts approvers using `SystemNotification`. The result is shown in the employee Blade views.
